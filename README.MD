# Сервис управления рассылками

Веб-приложение на Django для создания и управления email-рассылками.

Приложение позволяет создавать получателей, сообщения и рассылки, выполнять отправку писем через SMTP-сервер, отслеживать результаты отправок и управлять пользователями с помощью роли менеджера.

## Возможности

### Получатели

Пользователь может:

* создавать получателей;
* редактировать получателей;
* удалять получателей;
* просматривать только собственных получателей.

Для каждого получателя хранятся:

* email;
* ФИО;
* комментарий.

Email получателя является уникальным.

### Сообщения

Пользователь может:

* создавать сообщения;
* редактировать сообщения;
* удалять сообщения;
* просматривать собственные сообщения.

Сообщение содержит:

* тему;
* текст сообщения.

### Рассылки

Пользователь может создавать рассылки, указывая:

* время начала;
* время окончания;
* сообщение;
* список получателей.

Рассылка автоматически получает статус:

* **Создана** — время отправки ещё не наступило;
* **Запущена** — текущее время находится в заданном интервале;
* **Завершена** — время окончания прошло;
* **Отключена** — рассылка была отключена менеджером.

Отправка разрешена только в пределах заданного временного интервала.

### Отправка писем

Для отправки используется SMTP-сервер Яндекса.

Каждому получателю отправляется отдельное письмо.

Для каждой попытки отправки сохраняется:

* время попытки;
* статус;
* ответ сервера;
* связанная рассылка.

Возможные результаты:

* **Успешно**
* **Не успешно**

### Авторизация

В приложении реализованы:

* регистрация;
* подтверждение email;
* вход;
* выход;
* восстановление пароля;
* установка нового пароля.

В качестве идентификатора пользователя используется email.

### Роли пользователей

В приложении предусмотрены две роли:

#### Пользователь

Обычный пользователь может:

* работать со своими получателями;
* работать со своими сообщениями;
* создавать и управлять своими рассылками;
* просматривать историю отправок своих рассылок.

Пользователь не имеет доступа к данным других пользователей.

#### Менеджер

Менеджер дополнительно может:

* просматривать всех пользователей;
* блокировать и разблокировать пользователей;
* просматривать все рассылки;
* просматривать статистику отправок;
* отключать и включать рассылки.

Менеджер не может редактировать или удалять чужие данные.

### Статистика

На главной странице отображается:

* количество всех рассылок;
* количество активных рассылок;
* количество уникальных получателей.

Для менеджера дополнительно отображается:

* общее количество попыток отправки;
* количество успешных отправок;
* количество неуспешных отправок.

## Кеширование

В проекте реализовано двухуровневое кеширование.

### Серверное кеширование

Для хранения кеша используется Redis.

Статистика главной страницы кешируется на 60 секунд.

Используется backend:

```text
django-redis
```

При изменении данных, влияющих на статистику, кеш инвалидируется.

### Клиентское кеширование

Для главной страницы устанавливается HTTP-заголовок:

```text
Cache-Control: private, max-age=60
```

Это позволяет браузеру использовать полученный ответ в течение 60 секунд.

## Установка

### 1. Клонирование проекта

```bash
git clone <URL_РЕПОЗИТОРИЯ>
cd newsletter_application
```

### 2. Установка зависимостей

Если используется Poetry:

```bash
poetry install
```

Активировать виртуальное окружение:

```bash
poetry shell
```

Либо выполнять команды через:

```bash
poetry run python manage.py ...
```

## Настройка переменных окружения

Создайте файл `.env` в корне проекта.

Пример:

```env
SECRET_KEY=your_secret_key
DEBUG=True

DB_NAME=your_database
DB_USER=your_user
DB_PASSWORD=your_password
DB_HOST=localhost
DB_PORT=5432

REDIS_URL=redis://127.0.0.1:6379/1

EMAIL_HOST_USER=your_email@yandex.ru
MAIL_PASSWORD=your_smtp_password
```

Файл `.env` не должен добавляться в Git.

## PostgreSQL

Перед запуском приложения необходимо создать базу данных PostgreSQL и указать её параметры в `.env`.

После настройки базы применить миграции:

```bash
python manage.py migrate
```

## Redis

Для работы серверного кеширования должен быть запущен Redis.

Проверить доступность Redis можно командой:

```bash
redis-cli ping
```

Ожидаемый результат:

```text
PONG
```

В проекте Redis используется через `django-redis`.

Адрес Redis задаётся переменной:

```env
REDIS_URL=redis://127.0.0.1:6379/1
```

## Создание суперпользователя

Для создания пользователя с правами менеджера:

```bash
python manage.py createsuperuser
```

Необходимо указать email и пароль.

В проекте суперпользователь автоматически получает роль:

```text
MANAGER
```

Запустить сервер разработки:

```bash
python manage.py runserver
```

После запуска приложение будет доступно по адресу:

```text
http://127.0.0.1:8000/
```

## Отправка рассылки

Для отправки необходимо:

1. Создать получателей.
2. Создать сообщение.
3. Создать рассылку.
4. Указать время начала и окончания.
5. Выбрать сообщение.
6. Выбрать получателей.
7. Запустить рассылку в разрешённый временной интервал.

Если текущее время находится за пределами интервала, отправка будет отклонена.

Если рассылка отключена менеджером, отправка также невозможна.

## История отправок

Для каждой рассылки доступна история попыток отправки.

В истории отображаются:

* дата и время;
* статус;
* ответ SMTP-сервера.

Это позволяет определить, какие письма были отправлены успешно, а какие завершились ошибкой.
